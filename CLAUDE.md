# CLAUDE.md — танковая арена (хакатон FunFlow)

Рабочее название: **Tank Brawl** (поменять, когда придумаем). Мобильная 2D-игра, вид сверху.
Вайб Battle City (танчики с Денди) + динамика Brawl Stars. Отвечай команде по-русски,
идентификаторы в коде — по-английски.

## Стек
- Unity 6.6 (6000.6.x), C#, шаблон Universal 2D (URP 2D Renderer). Точная версия — `ProjectSettings/ProjectVersion.txt`.
- Основная платформа — Android, горизонтальная ориентация, цель 60 FPS (`Application.targetFrameRate = 60`).
- Ввод — только новый Input System (пакет `com.unity.inputsystem`). Старый `Input.GetAxis/GetKey` не использовать.
- Физика — Physics 2D.
- Редактор Unity подключён через MCP (инструменты `Unity_*`).

## Игровая концепция (источник правды — если код расходится с этим разделом, спроси)
- **Числа баланса** (скорости, урон, перезарядки, длительности, HP) берём из `tank_balance_v0_2.md` — он новее этого раздела и имеет приоритет. Потом подгоняем по плейтестам.
- **Масштаб:** 1 юнит Unity = 1D (диаметр танка). Клетка Tilemap = 1 юнит = целый блок (танк = 1 клетка; раньше были четвертинки 0,5, от них отказались). Спрайт блока 64×64 px при 64 PPU. Коллайдер танка — круг радиусом 0,45.
- **Движение свободное, не по сетке.** Карта собрана из тайлов (Tilemap), но танки ездят плавно.
- **Пушка всегда смотрит по направлению корпуса.** Прицеливание = руление. Отдельной башни нет.
- **Стик:** малое отклонение → разворот на месте без движения; сильное → езда. Скорость поворота корпуса — настраиваемая (стартовое значение 450°/с).
- **Снаряды крупные (почти в размер танка) и медленные** — скорость ненамного выше скорости танка. Вдали от них можно увернуться, вблизи попасть легко.
  - Два хитбокса у снаряда: для попадания по танкам крупнее, для столкновения со стенами заметно меньше, чтобы не цеплял углы.
  - Разные типы снарядов различаются силуэтом, а не только цветом.
- **Нитро:** тратится, само восстанавливается. Даёт ускорение и **таран**: на нитро танк ломает кирпич и наносит урон/отталкивает танк, в который врезался.
- **Павер-апы (временные):** взрывные снаряды (урон по радиусу), быстрая перезарядка, лазер (непрерывный луч 2–3 с, стены не ломает, замедляет танк на время стрельбы), щит (поглощает одно получение урона, сам спадает через 15 с с миганием за 2 с). Числа этапа 7 — в разделе «Что реализовано (этап 7)». Кнопка смены типа снаряда переключает доступные типы по кругу.
- **Карта** (каждый вид — отдельный тайлмап под `Grid`):
  - `Border` — край карты, нерушим, снаряд о него исчезает.
  - `Steel` — нерушимый рельеф (компонент `RicochetSurface`), снаряд отражается зеркально, до `maxBounces` раз (2); после первого отскока снаряд может попасть и в стрелка.
  - `Bricks` — кирпич (`DestructibleTilemap`), прочность 2, возрождается через 5 с с миганием за 0,6 с, не появляется под танком.
  - `Water` (слой `Water`) — непроходима для танков, снаряды пролетают.
  - `Bushes` (`BushTilemap`, без коллайдера) — вражеский танк в кустах невидим, свой полупрозрачный (`TankConcealment`). Для ботов — `IsHiddenFrom(Team observer)`; `IsConcealed` значит только «скрыт от игрока» и у танка игрока всегда `false`.
- **Экономика и прокачка (бесконечная, между матчами):** валюта — шестерёнки (12 за каждого врага, уничтоженного игроком, 100 за победу, 20 за доп. цель режима); пять веток улучшений (корпус, двигатель, орудие, скорострельность, нитро), цена `round(база · 1,35^n)`; сумма купленных уровней — ранг угрозы `R`, по которому растут боты. Числа и формулы — в `tank_balance_v0_2.md` §12–15, устройство в коде — «Что реализовано (этап 9)».
- **Цель дизайна — ближний бой.** Маленькие арены, павер-апы в спорных точках, мало HP, быстрая перезарядка.
- Автоприцел не делаем. Слабый доводчик 3–5° — только если плейтесты покажут промахи вблизи.
- Разные типы танков — **вне MVP**.

### Режимы игры (решение пользователя, записано после этапа 8, часть 1; **все три режима реализованы в этапе 9**, там же итоговые числа и отличия от этого текста)
Три режима. Базы — это только зоны появления, их не разрушают (прежнее предложение «защита и уничтожение базы» снято).
1. **Команда на команду, без возрождений в рамках раунда.** Раунд идёт до полного уничтожения команды противника, матч — до 3 или 5 побед (быстрая соревновательная сессия). В начале раунда все появляются на своих базах.
2. **Удержание точки в центре**, тоже командный. Очки идут команде, пока в радиусе флага в центре есть её танк. Победа по достижении лимита очков либо у кого больше за 7–10 минут. Возрождение через 5–10 с на базе своей команды.
3. **Deathmatch, все против всех, 4 танка** (у каждого свой цвет скина: есть Blue, Green, Red, Yellow). Возрождение через 5–10 с в случайной точке карты, 3 с неуязвимости с миганием. Очки за убийства и за выживание: после 20–30 с без смерти по N очков раз в 5 с. Итог по очкам.
- Все числа режимов (число побед, лимиты очков, время раунда/матча, респавн, N очков) — в SO-конфиге режима, не в коде.
- **Уточнено пользователем:** мультиплеера не будет, всегда один игрок-человек, остальные боты. В командных режимах 3 на 3 (человек + 2 союзных бота против 3 вражеских). В DM человек и 3 бота.
- **Решение пользователя о порядке:** «желательное» (ограничение обзора, карты с базами и точками появления, производительность на 9 ботах) пока не делаем. Сейчас сделано только поведение ботов под режимы (выбор цели с гистерезисом и состояние `Hold`, см. «Что реализовано (этап 8, часть 2)»); менеджер матча, модель команд, респавн, очки, камера погибшего — следующие шаги. **Обновление:** всё это сделано в этапах 8б и 9; из «желательного» по-прежнему не сделано ограничение обзора ботов (базы, точки появления и флаг на арене уже есть).

### Следствия режимов для кода (анализ; пункты 1–3 и 5 сделаны в этапах 8б–9, остаются ограничение обзора и проверка производительности на телефоне)
Что нужно, чтобы режимы заработали, по критичности:
1. **Модель команд.** `Team` — enum из двух значений (`Player`/`Enemy`), `Team.Player` жёстко зашит только в `TankConcealment` (`IsConcealed`, `VisibilityAlpha`) и как умолчание в `TeamMember`. Для DM нужно минимум 4 команды/идентификатора, плюс понятие «команда локального игрока» (кусты прячут чужих именно от неё, свой танк в кусте полупрозрачный). Снаряды, таран, уворот и `IsHiddenFrom(observer)` уже сравнивают команды, так что после обобщения работают. `TeamMember` лежит в `Scripts/Core` (общий интерфейсный файл).
2. **Менеджер матча** (`GameManager`, синглтон разрешён): режим как SO, раунды/очки/таймеры, появление, респавн (сейчас смерть = `SetActive(false)`, события `Died` без указания убийцы: нужен источник урона, он есть в `DamageInfo.Source`/владельце снаряда, но до `Died` не доходит), 3 с неуязвимости с миганием (в `TankHealth` есть окно после удара и мигание, но не отдельное «спавн-щит»), выбор безопасной случайной точки (не в стене, не рядом с врагом), зоны баз, флаг-зона с подсчётом очков, экран победы/поражения и счёт. Камера: в режиме без респавна погибший игрок должен смотреть за союзниками (`CameraFollow` сейчас следует за одной целью).
3. **Боты, обязательное** (пункты а и б **сделаны**, см. «этап 8, часть 2»; в — ждёт спавн-защиты): (а) **состояние удержания точки** для режима 2 — ехать в зону, оставаться в радиусе, отбиваться от врагов вокруг; без него боты в этом режиме просто охотятся за игроком и очки не набирают осмысленно; (б) **выбор цели при нескольких врагах** — в DM врагов трое, в командных до 5; нужен гистерезис (держать цель N секунд, менять, только если новая заметно ближе), ранее считалось «не критично при одном враге»; (в) не стрелять в неуязвимую цель (только что возродившуюся). Сброс состояния бота при возрождении уже есть (`OnEnable` → `ResetState`, `TankHealth.OnEnable` восстанавливает HP).
4. **Боты, желательное:** ограничение обзора (на больших картах для 5×5/DM «всеведение» заметнее, чем на маленькой арене); память на каждого врага — по-прежнему необязательна. Засады, «выглянул–выстрелил–спрятался», координатор/роли — **не делаем** (дорого, игрок почти не заметит; см. «Тактика ботов»).
5. **Карты:** командным режимам нужны базы и больше места, чем «маленькая арена»; для DM — набор точек возрождения; для режима 2 — флаг в центре. `PowerUpSpawner` масштабируется от размера карты, `BotNavGrid` работает на любой. Производительность: до 9 ботов на телефоне, каждый делает касты и сканирует снаряды (проверить на устройстве).
6. **Retreat у ботов** остаётся полезным в режиме без возрождений; в режимах с респавном (2 и 3) раненому боту отступать менее выгодно, возможно, ослабить через `BotProfile` или режим.

### Решённое
- **Таран** (в балансе чисел нет, стартовые значения — в SO, после плейтеста внести в баланс): работает только пока включено нитро и скорость выше порога. Урон танку 25 HP + отталкивание, кулдаун таранного урона на одну цель (~0,6 с), чтобы не бить каждый кадр. Кирпич на нитро ломается целиком за касание. Сталь и воду таран не ломает.
- Встречные снаряды разных команд уничтожают друг друга (баланс, раздел 5); снаряды одной команды пролетают друг сквозь друга и сквозь свои танки.
- Снаряды пролетают над водой.
- Срока жизни у снаряда нет: летит до первого попадания, арены должны быть замкнуты бортиком.
- Снаряд на 20% меньше, чем в балансе: диаметр 0,56 вместо 0,7D, радиусы хитбоксов 0,28 (по танкам) и 0,12 (по стенам). Решение команды, документ баланса это не отражает. Бронебойный, осколочный и бот-снаряд сделаны ещё уже (тонкий ствол с широким снарядом выглядел неестественно): радиусы 0,2 (по танкам) и 0,09 (по стенам), спрайт сужен до 0,7 по ширине (`Visual` повёрнут на 90°, поэтому сужается его локальный Y); у взрывного остаётся 0,28/0,12.
- **Павер-апы отличаются от `tank_balance_v0_2.md` (решения пользователя, документ не менялся):** щит держится 15 с с миганием за 2 с (в балансе 6 с); взрывные снаряды 7 с (в балансе 15), радиус взрыва 2,0 (у осколочного 1,4); интервал повторного урона лазера 0,65 с (в балансе 0,5). Быстрая перезарядка есть в концепции, но не в балансе. Когда баланс будут обновлять, внести эти числа туда.
- **Текстуры снарядов и павер-апов.** У снарядов свои спрайты (`Art/Projectiles/proj_*`); заглушки — пикапы и кольцо щита (круги). Настоящие текстуры пользователь добавит отдельной сессией; код менять не надо, достаточно заменить спрайты в префабах (силуэты снарядов разных типов должны различаться, а не только цвет).

## Боты
- У бота **те же ограничения, что у игрока**: тот же `TankController`, пушка по корпусу, перезарядка, нитро. Разница только в источнике ввода (см. архитектуру).
- Поиск пути: свой A* по сетке тайлов. Разрушенный кирпич → клетка становится проходимой. Путь сглаживается, танк едет по точкам.
- FSM: `Patrol/Seek` (к точке или павер-апу) → `Attack` (сблизиться и кружить) → `Ram` (рывок на нитро вблизи) → `Retreat` (мало HP: за укрытие/к павер-апу). `Dodge` — короткое прерывание любого состояния, если снаряд долетит за ~0,5 с.
- Стрельба: только при прямой видимости (raycast), кроме намеренного выстрела по кирпичу, перекрывающему путь.
- Характер — через `BotProfile` (ScriptableObject): агрессия, порог отступления, жадность к павер-апам, задержка реакции (0,2–0,4 с), разброс прицела.
- Читаемость: под каждым танком (игрока и ботов) тонкая небольшая полоска HP без цифр, не мешающая игре (решение пользователя). Дыма при малом HP нет. «Газ» (ускорение при спринте) пользователь добавит позже визуальным эффектом нитро для всех танков; отдельного «газования» бота перед тараном делать не надо.
- Против застревания: «не сдвинулся за 1 с → сдать назад и перестроить путь». Боты отталкиваются друг от друга.
- **Честная информация:** бот пользуется только тем, что доступно игроку (прямая видимость, кусты). Никакого «видит сквозь стены».

### Что реализовано (этап 3, `Scripts/AI`)
- `BotNavGrid` (объект `BotNav` в сцене): A* по **центрам клеток**, узел свободен, если свободна его клетка (танк = 1 клетка, проходит коридор шириной в 1 клетку). Solid-карты (Border, Steel, Water) блокируют всегда, Bricks — пока кирпич стоит. `Version` растёт, когда кирпич появляется/исчезает (по `Tilemap.tilemapTileChanged`); боты пересобирают путь при смене версии. Сглаживание — жадная «протяжка» проверкой круга радиусом `agentRadius` (0,45).
- `BotTankInput : ITankInput` (состояния этапа 3 `Idle` / `Chase` / `Engage` заменены FSM этапа 8, см. «Что реализовано (этап 8, часть 1)»). Видимость — `CircleCast` радиусом стенового хитбокса снаряда по слою `Wall` (вода не мешает), раз в `perceptionInterval`. Стрельба: видимость + дистанция `fireRange` + корпус выровнен с прицелом (`fireAlignTolerance`) + прошла задержка реакции + впереди нет стали ближе `steelPointBlankDistance`. Прицел = позиция цели с упреждением `leadFactor` + случайный разброс ±`aimSpreadDegrees` (пересчитывается после каждого выстрела по событию `TankWeapon.Fired`).
- Танк ездит только вперёд по корпусу, поэтому «сдать назад» = развернуться и отъехать (`reverseDuration`).
- Конфиги: `ScriptableObjects/Tank/BotTankConfig`, `Weapons/BotWeapon`, `Bots/DefaultBotProfile`. Префаб `Prefabs/Tank/Bot` (вариант `Tank`, команда Enemy). Песочница `Scenes/Sandbox/Bots.unity` (копия Tank.unity без манекенов + `BotNav` + два бота).
- **Ограничения, известные на конец этапа 3** (часть снята в этапе 8, часть 1: цель в кустах больше не выбирается раньше видимой, потеряв цель бот патрулирует, в упор кружит): цель — ближайший по прямой враг чужой команды, выбирается раз в `retargetInterval` без гистерезиса (при двух равноудалённых может метаться); память одна (`lastKnownPosition` только текущей цели); боты не координируются.

### Что реализовано (этап 4, `Scripts/Tank`)
- `NitroConfig` (SO, `ScriptableObjects/Tank/NitroConfig`): и нитро, и таран в одном ассете (настраиваются вместе, прокачка по балансу меняет только `capacity`). Нитро из баланса: запас 3 с, скорость 5,0, регенерация 7%/с. Остальное — **предложения, в баланс не внесены**: `reactivateStock` 0,1, `ramMinSpeed` 4,0, `ramMaxAngle` 45°, `knockbackSpeed` 8 на 0,3 с, `brickBreakHalfWidth` 0,4, `ramBlockDamage` 99.
- `TankNitro` читает `ITankInput.NitroHeld`. Запас тратится, пока кнопка зажата **и танк едет** (`TankController.IsDriving`); иначе восстанавливается. После опустошения нитро заблокировано до `reactivateStock`. Публично: `Current`, `Max`, `Normalized`, `IsActive`, `IsLocked`, `Speed`. `[DefaultExecutionOrder(-10)]`, чтобы контроллер видел состояние этого шага.
- `TankController` берёт `nitro.Speed`, пока нитро активно. Отталкивание: `ApplyKnockback(velocity, duration)` — скорость добавляется к скорости езды и линейно затухает (импульс на теле не работает, контроллер каждый шаг перезаписывает `linearVelocity`).
- `TankRam` (`OnCollisionEnter2D`/`Stay2D`): только при активном нитро, скорости ≥ `ramMinSpeed` и препятствии в пределах `ramMaxAngle` от курса. Танк чужой команды: урон 25 через `TankHealth.TakeDamage` + отталкивание, кулдаун 0,6 с на цель. Если цель неуязвима (`TankHealth.IsInvulnerable`), удар пропускается целиком и кулдаун не тратится. Местность (`IDamageable.Kind == Terrain`): `Amount = 0`, `BlockDamage = ramBlockDamage` в трёх точках по ширине корпуса. Сталь и вода не `IDamageable`, поэтому не ломаются.
- Бот: поля `nitroRamDistance`, `nitroStartStock`, `nitroStopStock`, `nitroAlignTolerance` в `BotProfile`; `BotTankInput.WantsRam` (нужен `directClear`). Состояние `Ram` сделано в этапе 8, часть 1 (без «газования» на месте: визуал ускорения будет общим эффектом нитро).
- `TankNitro` и `TankRam` лежат на базовом `Prefabs/Tank/Tank` (варианты Player и Bot наследуют). Песочница `Scenes/Sandbox/Nitro.unity` (копия Bots + стенд вокруг (0, 8): кирпичная стенка, сталь, вода, пассивные «жертвы» Enemy и союзник; боты в ней выключены).

### Что реализовано (этап 8, часть 1: состояния и реакция ботов, `Scripts/AI`, `Scripts/Tank`)
Тактический слой (выбор цели, память на каждого врага, засады, координатор) **не делался**, это часть 2.
- **FSM** в `BotTankInput` (разбит на `partial`-файлы: `BotTankInput.cs` — ядро, атака, таран, патруль, путь; `.Dodge.cs`; `.Retreat.cs` — отступление и павер-апы). Состояния `BotState`: `Patrol`, `Seek`, `Attack`, `Ram`, `Retreat`, `Dodge` (`Idle/Chase/Engage` убраны). Решения принимаются раз в `decisionInterval` (0,3 с ±15%), руление и стрельба — каждый кадр. Приоритет в `ChooseState`: Retreat (липкое) → Ram (липкое) → поход за пикапом → Attack (есть прямая видимость и дистанция ≤ `fireRange`) → Seek (знаем, где враг) → Patrol. `Dodge` — оверлей: перебивает всё, `State` возвращает `Dodge`, пока он идёт.
- **Patrol:** случайная свободная точка карты (`BotNavGrid.TryGetRandomPoint`, не ближе `patrolMinDistance`), по приезде или через `patrolMaxTime` или если путь не строится — новая. **Seek:** едет по A* к `lastKnownPosition` (если враг не в кустах, она обновляется каждый кадр: **бот знает позицию любого врага вне кустов на всей карте, сквозь стены и без ограничения дальности**; это отступление от «честной информации», у игрока обзор ограничен камерой ≈ ±9 × ±5 юнитов; то же с пикапами; ограничить обзор — задача части 2) или к пикапу; приехал в последнюю точку, а врага не видно — след остывает, бот патрулирует. Попутно стреляет, если корпус случайно смотрит на цель.
- **Attack (не стоит на месте):** пока пушка перезаряжается — кружит вокруг цели (`CircleHeading`: касательная ± радиальная добавка к `preferredDistance`, зона смешивания `distanceBand`, сторона меняется раз в `strafeSwitchMin…Max` с); за `aimLeadTime` до готовности пушки разворачивается на цель (на месте, если ближе `preferredDistance + distanceBand`, иначе едет к ней) и стреляет при выровненном корпусе. Раз в решение проверяется, не упирается ли кружение в стену (`BotNavGrid.IsSegmentWalkable`): другая сторона → кружение без радиальной добавки → прямо на цель. Если на танке лазер (`TankWeapon.Suppressed`), бот всё время держит прицел и сближается. Для этого добавлено `TankWeapon.CooldownLeft`.
- **Ram:** вход из Attack/Seek, если есть прямой путь (`directClear`), цель ближе `nitroRamDistance`, запас нитро ≥ `nitroStartStock`, корпус смотрит на цель в пределах `nitroAlignTolerance` и выпал шанс `aggression`. Едет прямо на цель, нитро включено, только пока корпус смотрит на неё (на месте не «газует»). Выход: запас ≤ `nitroStopStock`, потеряна прямая видимость, цель дальше 1,5× `nitroRamDistance`, прошло `ramMaxDuration`; потом пауза `ramCooldown`. Стреляет во время тарана, если выровнен.
- **Retreat:** при HP ≤ `retreatHealthFraction` (и враг известен). Цель по порядку: безопасный пикап в `retreatPickupDistance` (бот ближе к нему, чем враг, и враг дальше `retreatCornerDistance` от него) → иначе укрытие: `coverSamples` случайных точек в кольце `coverMinDistance…coverMaxDistance`, оценка = «не простреливается врагом» (+10) + удалённость от врага − длина пути; если уже вне линии огня — остаётся на месте. В укрытии стоит, повернув пушку в сторону последней позиции врага. Каждые `coverReplanInterval`, пока враг его видит, выбирает укрытие заново. Конец: `retreatDuration` (HP не восстанавливается, поэтому отступление обязано кончаться само) или «загнан»: враг с прямой видимостью ближе `retreatCornerDistance` (тогда бой). После конца `retreatLockout` с повторно не отступает. На бегу стреляет, если корпус случайно выровнен.
- **Dodge** (`.Dodge.cs`): раз в `perceptionInterval` перебирает `Projectile.InFlight` (публичный список только для чтения; добавлены `Team`, `Direction`, `Config`, `IsFinished`). Угроза: чужой снаряд в радиусе `dodgeSightRange` (≈ половина ширины экрана), который заденет корпус (радиус корпуса + `tankHitRadius` + `dodgeMargin`) за `dodgeLookahead` (0,5 с), и между ними нет стены (рикошеты не предсказываются). Честность: снаряды видны игроку везде на экране (кусты прячут только танки), поэтому ограничение — радиус, человеческая задержка `dodgeReactionMin…Max` и шанс `dodgeChance` (бросок на каждую угрозу). Манёвр: шаг перпендикулярно траектории в сторону, где свободно (`dodgeDistance`), предпочитая ту, где бот уже стоит, и ту, что ближе к курсу; длится ≤ `dodgeDuration` или пока снаряд не пролетел/не исчез; при `timeToHit < dodgeNitroTime` включает нитро. Во время уворота не стреляет.
- **Павер-апы:** `PowerUpPickup.OnMap` (реестр, только чтение) и `ClaimedBy` (кто едет за пикапом: второй бот выбирает другой, это не замок). Бот хочет пикап, если тот не занят другим, такого эффекта на нём ещё нет, путь к нему строится и прямая дистанция ≤ `powerUpMaxDistance × powerUpGreed` (в бою, когда есть чистый выстрел, — `combatPowerUpDistance × powerUpGreed`). Едет, пока не подберёт, пикап не исчезнет или не пройдёт `powerUpGiveUpTime`; недостижимый пикап на 5 с забывается. Щит и лазер бот сам не «включает»: это эффекты танка.
- **Честная информация:** `PickTarget` больше не выбирает врага в кусте (раньше знал его позицию), кроме текущей цели — к ней бот идёт по последней известной точке.
- **Характеры:** `BotProfile` — один ассет на характер. `DefaultBotProfile` (уравновешенный), `BotProfile_Aggressor` (aggression 0,9, дистанция 3, отступает при 15% HP, жадность 0,4, уворачивается в 50%) и `BotProfile_Cautious` (aggression 0,15, дистанция 6, отступает при 55% HP, жадность 0,9, уворот 85%, реакция медленнее, разброс меньше) в `ScriptableObjects/Bots`. В песочницах `Bots` и `PowerUps` `Bot_A` = агрессор, `Bot_B` = осторожный. Поле `stopDistance` удалено, вместо него `preferredDistance` и `distanceBand`.
- **Полоска HP** (общий компонент, не часть ботов): `TankHealthBar` на дочернем объекте `HealthBar` (с детьми `Back`, `Fill`) базового `Prefabs/Tank/Tank` (Player и Bot наследуют) и `TargetDummy`; стиль — `ScriptableObjects/Tank/HealthBarStyle` (ширина 0,7, толщина 0,08, смещение (0; −0,72) в мировых осях, порядок 15, цвета от зелёного к красному, фон, `hideWhenFull`, `fadeSpeed`). Не вращается с корпусом (каждый `LateUpdate` ставит мировую позицию и нулевой поворот). Спрайт — общий белый 1×1, создаётся в рантайме. Чужой танк в кусте: полоски нет (`TankConcealment.VisibilityAlpha` = 0), свой — полупрозрачный вместе с танком. `TankHealth` и `TankConcealment` игнорируют рендереры полоски (`TankHealthBar.FindTankRenderers`), чтобы она не мигала при ударе и не красилась кустами. **Решение пользователя:** полоска видна всегда (`hideWhenFull = false` в `HealthBarStyle`); если когда-нибудь станет мешать, включить `hideWhenFull` — полоска появится только с первым попаданием.
- **Автотесты (Play Mode, `PowerUps.unity`):** боты сами подбирают пикапы (Bot_A взрывной, Bot_B — четыре подряд), переходят Seek → Attack; уворот: из 31 снаряда в ботов попало 5 (осторожный увернулся от 24 из 26, агрессор от 2 из 5, как и задумано шансами); отступление: Seek → Retreat → безопасный щит → остался в укрытии → выход по `retreatDuration` → блокировка → повтор; Ram: за 40 игровых секунд бот входил в таран дважды, урон тараном (−25 HP) прошёл, снаряды ботов попадали; без игрока оба бота патрулируют в разных частях карты; скриншот игровой камеры: полоски под танком игрока и бота видны, тонкие. **Не перепроверено после правки:** кружение у стены (бот зажат между игроком и стеной: раньше менял сторону каждый тик и дрожал, теперь по цепочке «другая сторона → без радиальной добавки → прямо на цель») — код компилируется, но поведение в той же ситуации повторно не смотрели. **Не проверено на ощупь:** баланс увода/шансов, насколько кружение выглядит «живым», поведение на большой арене, на телефоне.
- **Известные ограничения / что осталось на часть 2:** цель по-прежнему ближайший враг по прямой (метание при двух равноудалённых); память одна; боты не координируются (развод по пикапам — только через `ClaimedBy`); укрытие выбирается случайной выборкой, без анализа карты (в засаду бот не встаёт); Retreat без восстановления HP кончается по таймеру, возвращая бота в бой раненым (нужен ремонт из баланса, раздел 7, или режим игры); во время уворота бот не стреляет; рикошет в предсказании уворота не учитывается; при очень близком выстреле (< ~0,3 с) уворот не успевает.
- В `Sandbox/PowerUps.unity` пользователь вручную выключал у `Bot_A` и `Bot_B` `TankWeapon` и `TankNitro`; по его просьбе включены обратно и сцена сохранена.
- **Подводный камень тестов:** окно Unity без фокуса тикает ≈0,4× реального времени, длинные наблюдатели на `EditorApplication.update` идут по реальному времени. `GetInstanceID()` в 6.6 — ошибка компиляции (`GetEntityId()`), `Unity_Camera_Capture` с числом из `EntityId` не работает: кадр игровой камеры снимай сам (`Camera.Render` в `RenderTexture` → PNG → Read).

### Что реализовано (этап 8, часть 2: боты под режимы, `Scripts/AI`, `Scripts/Map`)
Сделано только поведение ботов (по решению пользователя); менеджер матча, модель команд, респавн, очки — нет.
- **Зона точки:** `CapturePointZone` (`Scripts/Map`, центр = позиция объекта, `radius`, `Contains(point)`, `Primary` — первая активная зона, реестр сбрасывается в `SubsystemRegistration`, кольцо рисуется гизмо). Подсчёт очков позже сделает менеджер матча. **Наличие зоны в сцене = режим «удержание точки»**: нет зоны — боты её игнорируют.
- **Состояние `BotState.Hold`** (`BotTankInput.Hold.cs`). Каждый бот при появлении бросает кубик `pointDuty` (0..1, в `BotProfile`: по умолчанию 0,7, агрессор 0,5, осторожный 0,9) и становится «держателем» или «охотником» (охотники ведут себя как раньше). Держатель, когда нет чистого выстрела (`canShoot` ложно) и пикап не нужен, едет в зону и ходит между случайными точками внутри неё (`BotNavGrid.TryGetPointAround`, не дальше 0,7 радиуса, новая точка каждые `holdSpotInterval` = 4 с), пушка повёрнута туда, где был враг, стреляет попутно, если корпус выровнен. Когда чистый выстрел есть — обычный `Attack`, но кружение притягивается к зоне (`PullToPoint`: чем дальше от края, тем сильнее, полная сила на `pointLeash` = 3 за краем, множитель `pointPull`). Приоритет в `ChooseState`: Retreat → Ram → пикап → Attack → **Hold** → Seek → Patrol.
- **Выбор цели с гистерезисом** (`PickTarget`): кандидаты — только видимые враги (не в кустах); цель держится минимум `targetHoldTime` (2 с), менять на другую можно, только если новая ближе текущей в `retargetDistanceRatio` (0,7) раз; цель, ушедшая в куст, сразу заменяется любым видимым; если видимых нет, бот держит спрятавшуюся цель и едет в её последнюю точку. Агрессор переключается охотнее (1,5 с, 0,8), осторожный упрямее (3 с, 0,6). Сравнение по прямой, не по пути.
- **Исправление по ходу:** если путь к врагу не строится (враг в кармане, не связанном с ботом картой), `Seek` раньше вставал навсегда; теперь бот на 5 с (`UnreachableForgetTime`) уходит в `Patrol` и потом пробует снова (`seekBlockedUntil`); недостижимый пикап так же забывается.
- **Песочница `Scenes/Sandbox/Point.unity`** (копия `Bots`, пункт «Точка 3×3» в меню, сцена в Build Settings): зона радиусом 3 в центре (0,5; 0,5); команда игрока — `PlayerTank` + `Ally_1`, `Ally_2` (боты `Team.Player`, скин Blue) в углу (−10,5; −10,5); враги `Bot_A`, `Bot_B`, `Bot_C` (`Team.Enemy`) в углу (10,5; 10,5). Профили: `Bot_A`, `Ally_1` — агрессор, `Bot_B`, `Ally_2` — осторожный, `Bot_C` — по умолчанию. Точки появления проверены по `Ground` и твёрдым тайлмапам (первая расстановка выдала точки за границей карты и бот не мог дойти — исправлено).
- **Автотест (Play Mode ×3, Point.unity):** все боты сходятся в центр, держатели стоят в зоне (`z1` в снимках), идут бои союзники против врагов, цели меняются без метания, зависших нет (кроме найденного и исправленного случая с недостижимой целью). Итог за 60 игровых секунд не получен (тест прерван: к тому времени пали 3 из 5 ботов, без респавна). **Не проверено на ощупь:** сколько держателей реально остаётся в зоне при 3 ботах (кубик `pointDuty`), удобно ли союзникам и игроку, как выглядит толпа в зоне.
- **Не сделано:** ограничение обзора (остальное, что здесь значилось — спавн-защита, 4 команды, «команда локального игрока», — сделано в этапе 8б). В Point.unity союзные боты и человек в одной команде, поэтому враги выбирают цель из трёх.

### Что реализовано (этап 8б: команды, спавн-защита, источник убийства; `Scripts/Core`, `Scripts/Tank`)
- **Команды.** `Team`: `Player = 0`, `Enemy = 1`, `Third = 2`, `Fourth = 3` (старые значения в сценах и префабах не менялись). «Команда локального игрока» — статическое `TeamMember.LocalTeam` (по умолчанию `Player`, сбрасывается в `SubsystemRegistration`); его выставляют `PlayerTankInput.OnEnable` и `MatchManager`. `TankConcealment.IsConcealed` / `VisibilityAlpha` берут `LocalTeam`: чужих кусты прячут от команды человека, свои (союзники тоже) полупрозрачные. `TeamMember.SetTeam(Team)` — менеджер матча переставляет команды в DM. `TeamColors` (`Scripts/Core`): цвет и название каждой команды (синие, красные, зелёные, жёлтые).
- **Спавн-защита** (`TankHealth`): `GrantSpawnProtection(секунды)` (звать после активации), `HasSpawnProtection`; `IsInvulnerable` включает и её. Мигание отдельное от окна после удара: `TankConfig.spawnBlinkInterval` (0,15 с против 0,05 с). `OnEnable` защиту сбрасывает. Боты не стреляют (`CanFire`, через него идут и попутные выстрелы) и не входят в таран (`WantsRam`) по цели с `HasSpawnProtection`.
- **Источник убийства.** `TankHealth.Died` — `Action<TankHealth, GameObject>` (жертва, `DamageInfo.Source`: корень танка-стрелка, может быть `null`), вызывается до `SetActive(false)`; на этот момент `IsDead` уже истинно, объект ещё активен. Новые события: `Damaged(health, amount, source)` (только если HP реально потеряно), `ShieldAbsorbed`. `TankController.OnDisable` обнуляет `currentSpeed`.

### Что реализовано (этап 9: режимы, награды, прокачка, меню, HUD, звук, эффекты)
Задача «доделать матчи до играбельного состояния»: три режима, экран итога, меню, настройки, киллтаб, шестерёнки и прокачка, звук и эффекты. Цифры режимов и экономики — **первый баланс от Claude** (пользователь доверил), подправить на плейтестах.

**Режимы и менеджер матча** (`Scripts/Match`, namespace `TankBrawl.Match`):
- `MatchManager` (синглтон `Instance`, один на сцену арены; без него сцены работают как раньше). Режим берёт из `MatchSession.Selected` (выбор меню), а при запуске сцены напрямую (из редактора) — из своего поля `config`. В `Start`: собирает танки (`MatchParticipant`: человек = с `PlayerTankInput`, имя «Я», боты «Бот N»), ставит скины по командам (`teamSkins`: синий, красный, зелёный, жёлтый), включает/выключает объект зоны (`capturePoint`) по режиму, создаёт режим (`CreateMode` — единственное место, куда добавлять режимы), HUD, подписывается на `Died`.
- Для режимов: `RespawnAll()` (стирает снаряды, возвращает кирпичи `DestructibleTilemap.ResetAll()`, сбрасывает спавнер павер-апов `PowerUpSpawner.ResetSpawner()`, ставит все танки на точки, камера `Snap()`), `Respawn(p)`, `ScheduleRespawn(p, задержка)`, `CountAlive/CountAll`, `FindParticipant`, `FinishMatch(MatchOutcome)`. Смерть только записывается (`Kills`/`Deaths`, `IMatchMode.OnDied`, событие `KillRegistered`); решения — в `Update`, не в колбэке урона. Награда за килл человека (`PayKill`) выдаётся сразу: `+gearsPerKill`, звуки `KillConfirm` и `GearGain`. Свой выстрел-рикошет (убийца = жертва) никому не засчитывается.
- Спавн: командные режимы — точки базы команды (`SpawnPoint.Team`, по номеру танка в команде; при респавне в разгар матча пропускаются точки, где стоит живой танк); `MatchModeConfig.randomSpawn` (DM) — случайная из `SpawnPoint.FreeForAll`, не ближе `safeSpawnDistance` (6) к живым врагам, если таких нет — самая дальняя. Спавн-защита `spawnProtection` на каждое появление, включая начало раунда.
- Конец матча: `FinishMatch` → замедление 0,25× на 1,4 с реального времени → `timeScale = 0` и экран результата. Пауза (`SetPaused`) тоже через `timeScale`. `OnDestroy` менеджера возвращает `timeScale = 1`. Клавиша «назад» (Escape / кнопка МЕНЮ сенсорного управления): в матче пауза, на экране итога — выход (`SceneNavigator.GoBack` → `MatchManager.OnBackPressed`).
- `IMatchMode` (интерфейс режима): `Begin`, `Tick`, `OnDied`, тексты `TitleText/TimerText/BannerText/HintText` (кэшированные строки), `ScoreVersion` + `Scores` (`ScoreEntry`: команда/метка/значение/деталь/«свой»). `MatchModeBase` — общий код (часы раз в секунду, подсказка «возрождение через N»). Режимы:
  - `EliminationMode` (команда на команду): раунды без респавна, до `roundsToWin` (3) побед; раунд кончается, когда живые остались у одной команды (ни у кого — ничья без очка); интро-баннер `roundIntroSeconds` 2, пауза `roundEndSeconds` 3. Доп. цель: человек ни разу не погиб (+20).
  - `CapturePointMode` (точка): очко в секунду (`pointsPerSecond`) команде, у которой в зоне живой танк только её; танки обеих команд = спор, очки никому. До `scoreLimit` (100) или `timeLimit` (480 с); при ничьей по времени — дополнительное время до первого очка перевеса. Респавн `respawnDelay` 7 с на базе, защита 3 с. Зона красится цветом владельца. Доп. цель: 30 с в зоне, пока команда набирает очки (+20).
  - `DeathmatchMode` (все против всех): человек + 3 бота, каждый своя команда (синий, красный, зелёный, жёлтый), остальные танки сцены (союзники) выключаются. 10 очков за убийство, после 25 с жизни +1 очко раз в 5 с (счётчик сбрасывается смертью). До 100 очков или 420 с; ничья за первое место = дополнительное время. Респавн 7 с в случайной свободной точке, защита 3 с. Доп. цель: 5 убийств (+20). Победа человека = первое место.
- `MatchModeConfig` (SO, `ScriptableObjects/Match/{TeamElimination,CapturePoint,Deathmatch}`): все числа режимов (название и описание для меню, защита, респавн, случайный респавн, лимиты времени и очков, раунды, очки точки, очки DM, доп. цель). Создаются и обновляются `TankBrawl/Setup Data Assets` (`Assets/_Project/Editor/ProjectSetup.cs`).
- `SpawnPoint` (команда или `freeForAll`; ось Y = куда смотрит танк), `MatchSession` (статика: выбранный режим), `MatchResult`/`MatchOutcome`/`ResultRow`/`RewardLine` (данные экрана итога).

**Арена** `Scenes/Arena.unity` (в Build Settings индекс 1; бывшая `Sandbox/Match.unity`, карта та же, что в Point/Match): все три режима на одной карте (новые карты — см. «Карты» ниже, теперь их строит генератор). Объекты: `PlayerTank`, `Ally_1/2`, `Bot_A/B/C`, `MatchManager`, `SpawnPoints` (базы 3+3 по углам: синяя (−10,5; −10,5), красная (10,5; 10,5); 8 точек `Free_N` для DM), `BasePads` (полупрозрачные квадраты 3×3 под базами, заглушка), `CapturePoint` (зона радиусом 3 в центре (0,5; 0,5), видна как кольцо и диск), `PowerUpSpawner` + `PowerUpPoints` (9 точек: девять из них ближе к центру, не в углах-базах; 4 вида усилений, не больше 2 на карте). Пока идут бои, пикапы и кирпичи сбрасываются на начало каждого раунда.

**Награды и прокачка** (`tank_balance_v0_2.md` §12–15, `Scripts/Progress`, `Scripts/Tank/TankStats.cs`):
- Шестерёнки: 12 за каждого врага, уничтоженного человеком (сразу), 100 за победу, 20 за доп. цель; при поражении остаётся награда за убийства и выполненная доп. цель. Хранятся в `PlayerProgress` (PlayerPrefs, ключ `tankbrawl.progress.v1`, JSON: шестерёнки, уровни пяти веток, громкости, вибрация, матчи/победы). Настройки-ползунки сохраняются с задержкой 0,6 с (`FlushIfDue` из `AudioManager.Update`, на паузе и выходе приложения).
- Пять веток (`UpgradeBranch`): корпус (+10 HP за уровень), двигатель (+0,15 D/с), орудие (+4 урона бронебойному, +2 прямого и +1 по площади осколочному), скорострельность (+0,05 выстр/с, интервал = 1 / (1/база + 0,05·n)), нитро (+0,25 с). Цена `round(база · 1,35^n)`, базы 100/90/140/130/80, ограничения уровня нет. Числа «за уровень» лежат в тех же конфигах, что и база: `TankConfig.healthPerLevel/speedPerLevel`, `NitroConfig.capacityPerLevel`, `WeaponConfig.damagePerLevel/explosionDamagePerLevel/speedPerLevel/fireRatePerLevel` (на Player: 10/0,15, на Bot: 4/0,01; оружие бота 0,5/0/0,03/0,01). `ProgressionConfig` (SO в `ScriptableObjects/Resources`, цены, награды, названия, иконки веток) описывает ветки игроку.
- `TankStats` (на базовом префабе танка) хранит уровни: у человека — купленные, у бота — ранг угрозы `R` = сумма всех уровней игрока (корпус, двигатель, орудие, скорострельность; нитро у ботов нет), как в балансе §14 (HP бота 100+4R, урон 35+0,5R, скорость 2,6+0,01R, скорострельность 0,8+0,01R, скорость снаряда 9+0,03R). Союзные боты усиливаются так же, как вражеские. Читают: `TankHealth.Max`, `TankController.BaseSpeed`, `TankNitro.Max`, `TankWeapon` (`WeaponLevel/FireLevel/ProjectileSpeed`), `Projectile` (`Speed`, урон, взрыв) и `Explosion.Detonate(blastDamage…)`. Бот-прицел и уворот берут скорость снаряда из `Projectile.Speed`.
- Улучшения влияют и на тестовые сцены (Tank, Bots…), где есть человек и боты: покупка в меню действует везде. Сбросить: Настройки → Сбросить прогресс.

**Карты** (ветка `feature/maps`): кроме `Arena` есть «Перекрёсток» (24×24), «Река» (30×18, под горизонтальный экран) и «Лабиринт» (22×22, много кирпича). Каждая карта — текстовая раскладка в `Assets/_Project/Editor/MapLayouts/<Id>.txt` (легенда в файле: `.` земля, `#` сталь, `x` кирпич, `~` вода, `%` кусты, `1`/`2` точки баз по 3, `f` точки DM (8+), `p` точки усилений, `Z` центр зоны; бортик 2 клетки добавляется сам; комментарий — строка, начинающаяся с `# ` с пробелом). Сцены строит `Assets/_Project/Editor/MapBuilder.cs`, меню **TankBrawl → Maps → Build New Maps** (уже существующие сцены пропускает) и **Rebuild All Maps (overwrite)** (перезаписывает, ручные правки сцен пропадут): копирует `Arena.unity` в `Scenes/Maps/<Id>.unity` (менеджер, танки, спавнер, камера, свет те же), перерисовывает тайлмапы теми же тайлами, двигает `SpawnPoints` (лицом к зоне, шаг 45°), `PowerUpPoints` (и массив `spawnPoints` спавнера), `CapturePoint` (центр = среднее клеток `Z`, `radius` из заголовка `zone`), `BasePads`, танки и камеру, вызывает `CompressBounds` и добавляет сцену в Build Settings. **Без Unity не запускался**: первым делом после слияния запустить Build New Maps, проверить консоль и сыграть каждую карту во всех трёх режимах. Раскладки 180°-симметричны (базы равны) и проверены скриптом: всё проходимо без разрушения кирпича (сетка ботов по центрам клеток, диагональ — только если свободны обе боковые клетки), путь от каждой базы до зоны одинаковый. Выбор карты — переключатель «< КАРТА: … >» на экране режимов (`MenuScreens.maps`: подпись + имя сцены, по умолчанию Арена, Перекрёсток, Река, Лабиринт; карта без сцены в Build Settings не показывается, переключатель скрыт, если карта одна); выбор хранится в `MatchSession.MapScene`, «Ещё раз» перезапускает ту же сцену. Новая карта = новый `.txt` + Build New Maps + строка в `maps` у `MenuScreens` в `Menu.unity`. Без Unity раскладку проверяет `python3 Tools/maps/validate_map.py <файлы>` (симметрия, проходимость, маркеры, зона) и рисует превью из настоящих тайлов `python3 Tools/maps/render_map.py <файл> <out.png>` (нужен ImageMagick).

**Исправления по списку доработок** (ветка `feature/todo-fixes` поверх `feature/maps`, **в Unity не проверялись**, компиляция сверена без Unity): усиления «Ремонт» (+30 HP, `TankHealth.Heal`) и «Заряд нитро» (`TankNitro.Refill`) — мгновенные `PowerUpKind.Repair/NitroRefill` (в конце enum), спавнер добавляет их сам с числами по умолчанию (`addInstantPowerUps`; ассет того же вида в списке `powerUps` их заменяет), бот хочет их ниже `repairWantedBelow` / `nitroRefillWantedBelow`; пикап исчезает через `PowerUpSpawner.pickupLifetime` (20 с, мигает 3 с; положенные вручную не исчезают); зарядные точки нитро `NitroStation` (рисуют себя сами, перезарядка 12–16 с, маркер `n` в раскладках карт, сброс в начале раунда); таран — один удар за касание (`TankRam.ContactGap`); нитро не расходуется в упоре (`NitroConfig.minDrainSpeed`); взрыв не проходит сквозь стены (лучи по слою `Wall` в `Explosion` и `DestructibleTilemap.DamageArea`); доп. цель платится только при победе; обзор ботов ограничен экраном игрока (`BotProfile.viewHalfWidth/Height` 9×5: цели и пикапы вне него не видны); уворот предсказывает один рикошет от стали (и свой снаряд после отскока) и не мешает стрелять; кольцо цвета усиления под танком (`TankPowerUps`, создаётся в `Start`); виньетка попадания только по краям; настройка «Тряска экрана» (`PlayerProgress.ScreenShakeOn`); клик мышью по интерфейсу не стреляет; зона стика подрезается до safe area; на тестовой арене «Назад»/«ПАУЗА» выходит в меню только со второго нажатия за 2 с. Тактика ботов: цель выбирается по «стоимости» — длина пути по A* (а не по прямой), меньше для раненого врага (`woundedTargetPreference`) и для того, кто целится в бота (`threatTargetPreference`, `threatAngle`), гистерезис прежний (`retargetDistanceRatio` теперь от стоимости); со взрывными снарядами бот стреляет в укрытие рядом с целью, если взрыв её достанет (`splashReach`, проверка `Explosion.Reaches`), и не боится стали в упор (такие снаряды не отскакивают); потеряв цель, бот проверяет до `searchBushes` ближайших кустов (`searchRadius`, `searchTime`): подъезжает и простреливает куст с `searchShotDistance`. Отложено: память на каждого врага, засады, роли и координатор, путь в обход линий огня.

**Сложность ботов** (запрос пользователя после проверки на телефоне: боты стреляли слишком точно и поворачивались слишком быстро; **в Unity проверено только меню и применение к ботам, не ощущение**):
- Три уровня: «Лёгкая», «Средняя», «Сложная». `DifficultyConfig` (SO `ScriptableObjects/Resources/DifficultyConfig`, `Scripts/AI`, создаётся `TankBrawl/Setup Data Assets`) хранит массив `Level` и `defaultLevel` (1 = Средняя: её получают сцены, открытые напрямую, и отладочные). Уровень **не заменяет** `BotProfile`, а масштабирует его числа: `Level.CreateProfile` делает копию профиля (`BotTankInput.Awake` подменяет ею `profile`, копия уничтожается с ботом), поэтому агрессор остаётся агрессором на любом уровне. Множители: `reactionScale` (задержка выстрела и увода), `aimSpreadScale`, `aimWobbleDegrees` (медленный дрейф прицела на шуме Перлина, новое поле `BotProfile.aimWobbleDegrees`, используется в `AimDirection`), `fireAlignScale` (допуск выравнивания перед выстрелом), `leadScale`, `dodgeChanceScale`, `aggressionScale` (шанс тарана), `decisionScale`; `turnRateScale` (скорость поворота корпуса: `TankController.TurnRateScale`, у игрока 1) и `statScale` (множитель ранга угрозы для уровней бота в `TankStats`).
- Стартовые числа (первый вариант, крутить в плейтестах): Лёгкая — поворот ×0,45, ранг ×0,5, реакция ×2,5, разброс ×2,2, дрейф 6°, допуск ×3, упреждение ×0,3, увороты ×0,3, таран ×0,4, решения ×1,6; Средняя — 0,7 / 1 / 1,5 / 1,3 / 3° / 1,5 / 0,8 / 0,8 / 0,8 / 1,2 (примерно прежние боты, но «человечнее»: медленнее поворачиваются и целятся с дрейфом); Сложная — 0,9 / 1,3 / 1 / 0,8 / 1,5° / 1 / 1 / 1 / 1 / 1. Уровень действует на **всех** ботов, включая союзных.
- **Открытие.** Следующий уровень режима открывается победой в этом же режиме на уровне ниже. `PlayerProgress`: `unlockedDifficulty[3]` в сохранении (по режимам, порядок `MatchModeKind`; сброс прогресса их сбрасывает), `HighestUnlockedDifficulty`, `IsDifficultyUnlocked`, `UnlockNextDifficulty(режим, пройденный, число уровней)` (считается, только если пройденный уровень был открыт: сцена, запущенная из редактора напрямую, ничего не открывает), `UnlockAllDifficulties`. Победу фиксирует `MatchManager.BuildResult`, экран итога показывает уровень и строку «Открыта сложность: …» (`MatchResult.DifficultyName/UnlockText`). Игрок со старым сохранением начинает с «Лёгкой» во всех режимах.
- **Меню.** На карточке режима выбор «< Сложность: … >» над «В БОЙ»; закрытый уровень можно посмотреть, но не запустить («Закрыта: победите на …», кнопка выключена). Выбор запоминается в `MatchSession.LastDifficulty` (по умолчанию — самый высокий открытый), в матч уходит через `DifficultyConfig.Selected` (-1 = по умолчанию). «Ещё раз» играет тот же уровень. Отладка → «Открыть все сложности».
- **Не сделано (по минимуму):** награда за более высокую сложность не растёт (шестерёнки те же); сложность не показывается в HUD матча; не проверено в Play Mode: победа → открытие следующего уровня на экране итога, ощущение каждого уровня.

**Подводные камни этапа 9**
- Скриншоты: `ScreenCapture.CaptureScreenshot` в этом окружении захватывает только оверлейный интерфейс (мир чёрный); мир снимай через `Camera.Render` в `RenderTexture`.
- `Unity_RunCommand` не умеет удалять ассеты (`AssetDatabase.DeleteAsset`, `FileUtil.DeleteFileOrDirectory` дают «User interactions are not supported»): удалять файл + `.meta` из оболочки и дать Unity обновиться.
- Любой `RunCommand` помечает активную сцену «грязной» (`isDirty`), даже без правок. Перед `OpenScene(Single)` её сохранять; чужую сцену править `OpenScene(..., Additive)` + `SaveScene` + `CloseScene`.
- Правка скрипта при идущем Play Mode не останавливает его сразу: перед тестами остановить Play и дождаться компиляции.
- Тесты пишут в `PlayerPrefs` пользователя (шестерёнки, уровни): после тестов сбрасывать `PlayerProgress.ResetProgress()`.

### Тактика ботов (план этапа 8: имитация лёгкого стратегического мышления)
**Статус:** часть 1 сделана. Из этого плана на хакатон нужны только выбор цели с гистерезисом и (по желанию) ограничение обзора; остальное (засады, «выглянул–выстрелил–спрятался», координатор, память на каждого врага) отложено и делается только если плейтест покажет проблему (боты ездят колонной, зависают и т. п.). Новые обязательные вещи для ботов — из режимов игры, см. «Следствия режимов для кода». Ниже исходный план, не руководство к действию.
Простое «едет и стреляет» — скучно. Нужен отдельный тактический слой поверх FSM (FSM остаётся простой), решения раз в 0,25–0,5 с, без аллокаций, всё настраивается через `BotProfile`.
- **Выбор цели** (несколько врагов): оценка по близости *по пути*, видимости, низкому HP, «кто целится в меня»; гистерезис (держим цель минимум N с, меняем, только если новая заметно лучше). Память на **каждого** врага отдельно (последняя точка, время, затухание).
- **После потери цели:** идёт в последнюю точку, затем коротко осматривает окрестность и ближайшие кусты, а не стоит столбом.
- **Позиционирование вместо езды в упор:** путь со штрафом за открытые линии огня (подход через укрытия), «выглянул–выстрелил–спрятался» у кирпича/угла, кружение и страйф в `Attack`, подставляться, когда своя пушка заряжена.
- **Засада:** ждать в кустах у вероятного маршрута или павер-апа и стрелять первым.
- **Командная игра** (≥2 бота): общий координатор на сцене (компонент, не синглтон): роли «давит в лоб» / «заходит с фланга» (штраф пути за уже занятые маршруты), боты не лезут в одну линию огня, один может идти за павер-апом.
- **Отступление и контроль точек:** при малом HP — в укрытие или к павер-апу; спорные точки (павер-апы, зарядка нитро) бот занимает осмысленно.
- **Непредсказуемость:** рандом в решениях и «характеры» через `BotProfile` (агрессор, осторожный, засадник), чтобы боты не вели себя одинаково.
- Приёмка: плейтест с 2+ врагами у бота; бот не должен выглядеть как «ползёт по прямой». Для теста нескольких игроков в сцене ставится второй танк с `TeamMember = Player`.

## Архитектура
- Папки: `Assets/_Project/{Scripts,Prefabs,Scenes,ScriptableObjects,Art,Audio,Input}`.
  Скрипты: `Scripts/{Core,Tank,Weapons,PowerUps,AI,Map,UI,Input,Match,Progress,Audio}`; скрипты редактора — `Assets/_Project/Editor`. Неймспейсы `TankBrawl.<Папка>`.
- `ITankInput` — источник команд (направление, выстрел, нитро). Реализации: `PlayerTankInput` (Input System) и `BotTankInput` (FSM). `TankController` знает только интерфейс.

- Команды: компонент `TeamMember` (`Team`: `Player`, `Enemy`, `Third`, `Fourth`) на каждом танке. Снаряд проходит сквозь танки и снаряды своей команды.

- Оружие: `WeaponConfig` (SO) на тип снаряда, `TankWeapon` стреляет по `FireHeld` (публичны `Config` и событие `Fired`), `TankHealth` держит HP (смерть = деактивация объекта).
- Все настраиваемые числа — в ScriptableObject-конфигах (`TankConfig`, `WeaponConfig`, `PowerUpConfig`, `BotProfile`), без магических чисел в коде.
- Танк: `Rigidbody2D` + `CircleCollider2D` (круглый, чтобы обтекал углы). Движение в `FixedUpdate`.
- Сцены: главная арена `Scenes/Arena.unity` (один владелец), карты из генератора `Scenes/Maps/<Id>.unity` (правка раскладки — в `Editor/MapLayouts`, затем пересборка), песочницы `Scenes/Sandbox/<Область>.unity` для тестов своей части.
- Меню: `Scenes/Menu.unity` (индекс 0 в Build Settings), экраны строит `MenuScreens` (см. этап 9); тестовые сцены лежат в «Настройки → Отладка» (список `debugScenes` компонента `MenuScreens`, сцена должна быть в Build Settings, иначе кнопка выключена). `SceneNavigator` создаёт себя сам: Escape / кнопка «Назад» на Android в матче ставит паузу, в меню идёт на экран назад (на главном закрывает приложение), в остальных сценах возвращает в меню. Текст UI — обычный `UnityEngine.UI.Text` (TextMeshPro не импортирован).
- **Документация:** сайт DocFX в `Documentation/` (сборка `./Documentation/build.sh --serve`, правила — `Documentation/articles/writing-docs.md`, публикация на GitHub Pages при пуше в `dev`). Новый класс — `/// <summary>`; публичный член — `<summary>`, если имя не объясняет единиц и поведения; реализация интерфейса — `<inheritdoc/>`; поле инспектора — только `[Tooltip]` (попадает в таблицу «Параметры в инспекторе»); внутри методов `//` только на «почему». При изменении поведения поправить статью в `Documentation/articles` (и `Documentation/game`, если это видно игроку).

## Особенности Unity 6 / 6.6 (частые ошибки)
- **Fast Enter Play Mode включён, domain reload выключен:** статические поля и подписки не сбрасываются между запусками Play Mode. Каждое static-поле сбрасывать в методе с `[RuntimeInitializeOnLoadMethod(RuntimeInitializeLoadType.SubsystemRegistration)]`; от static-событий всегда отписываться в `OnDisable`/`OnDestroy`.
- `Rigidbody2D.linearVelocity` (не `velocity`), `linearDamping` (не `drag`).
- `FindObjectsByType<T>()` / `FindAnyObjectByType<T>()` вместо устаревших `FindObjectsOfType` / `FindObjectOfType`. В 6.6 `FindFirstObjectByType` и `FindObjectsSortMode` тоже deprecated.
- `LayerMask.GetMask` / `NameToLayer` нельзя вызывать из статических инициализаторов и конструкторов `MonoBehaviour` — только в `Awake`/`OnEnable`.
- Не создавай мусор в `Update` (LINQ, new в цикле): это мобилка.
- **Unity 6.6 не строит коллайдеры Tilemap при загрузке сцены** (композитный коллайдер пуст, танки и снаряды проходят сквозь стены). Лечит `Scripts/Map/TilemapColliderBootstrap` (выключает и включает каждый `TilemapCollider2D` при загрузке любой сцены). Не удалять; новым сценам и тайлмапам ничего добавлять не надо. Проверка: `CompositeCollider2D.shapeCount > 0` в Play Mode.
- `[RequireComponent]` принимает максимум 3 типа в одном атрибуте — для большего ставь несколько атрибутов.

## Работа с редактором через MCP
- Сцены, префабы, компоненты, ScriptableObject-ассеты меняй **только через инструменты MCP**. **Никогда не редактируй текст `.unity`, `.prefab`, `.asset`, `.meta` вручную.**
- После любой правки скриптов прочитай консоль (`Unity_GetConsoleLogs`). Ошибки компиляции чинить в первую очередь: пока они есть, MCP-мост не работает. Если видишь старые ошибки — попроси пользователя переключиться в окно Unity, чтобы прошла перекомпиляция.
- Новые `.cs` можно создавать файлами: `.meta` Unity сгенерирует сама. Перемещать/переименовывать ассеты — через Unity или вместе с `.meta`.
- Подводные камни MCP:
  - Unity в фоне почти не тикает: `EditorApplication.delayCall`, кадры Play Mode и перестройка коллайдеров Tilemap ждут, пока окно Unity получит фокус. Отложенный код может «выстрелить» намного позже.
  - `EditorApplication.isPlaying = true` срабатывает на следующем тике — следующий вызов делай после паузы и проверяй, что Play Mode реально запущен.
  - Сборку плеера через MCP не запускать: вызов блокирует редактор и отваливается по таймауту. Собирает человек (Build And Run), ты читаешь консоль.
  - Автотест движения без фокуса: виртуальный `Gamepad` + `Physics2D.simulationMode = Script` + ручные `FixedUpdate`/`Physics2D.Simulate`, затем вернуть режим.
  - `Unity_RunCommand` запрещает `System.Reflection`. Приватные методы вызывай через `gameObject.SendMessage("Метод", аргумент)`.
  - Play Mode тикает, пока окно Unity в фокусе, но между вызовами MCP проходит мало игрового времени: делай паузы (`sleep`) и читай результат отдельным вызовом. Нажатие клавиш: `InputSystem.QueueStateEvent(Keyboard.current, new KeyboardState(Key.Space))` и `InputSystem.Update()`; потом обязательно отпусти клавишу (`new KeyboardState()`) и останови Play Mode.
  - Детерминированный тест снарядов: `Instantiate` префаба, `Launch(...)`, затем цикл `SendMessage("Advance", 0.1f)` и лог позиций.
  - После правки кода Unity перекомпилируется: MCP недоступен, Play Mode останавливается. Дождись конца, потом запускай Play снова. Умерший танк деактивирован, `GameObject.Find` его не найдёт.
  - После `Tilemap.SetTile` коллайдер обновляется с задержкой: вызывай `TilemapCollider2D.ProcessTilemapChanges()` (в `DestructibleTilemap` это уже сделано).
  - После правки скриптов мост часто недоступен 1–2 минуты («Unity not detected»): просто повторяй `Unity_GetConsoleLogs` с паузами. Если Unity не импортировала новый файл, запусти через `Unity_RunCommand` `AssetDatabase.Refresh(ImportAssetOptions.ForceUpdate)`.
  - Один `Unity_RunCommand` выполняется за один кадр. Чтобы наблюдать поведение во времени, подпишись на `EditorApplication.update` (лог с `Debug.Log`, отписка по таймеру) и прочитай консоль следующим вызовом. Консоль фильтруй `logTypes`: `Info` для логов, `Error`/`Warning` для ошибок.
  - Числа в логах `RunCommand` идут с запятой (локаль): форматируй с `CultureInfo.InvariantCulture`.
  - `EditorUtility.CopySerialized` копирует и имя ассета: после копирования выставь `asset.name`. Префаб-вариант создаётся через `PrefabUtility.InstantiatePrefab` + `SaveAsPrefabAsset`. Копию сцены делай `AssetDatabase.CopyAsset`; перед `OpenScene` проверь `isDirty` и не сбрасывай чужие правки.
  - В тестах боты убивают неподвижного игрока за ~3 с, а `GameObject.Find` неактивного танка не находит. Для теста маршрутов выключи `TankWeapon` у ботов или оживи игрока (`SetActive(true)` восстанавливает HP) и переставь его через `Rigidbody2D.position` + `transform.position`.
  - Нажатия клавиш в тестах: окно Unity без фокуса сбрасывает состояние клавиатуры между тиками. Для **зажатой** клавиши ставь `QueueStateEvent` + `InputSystem.Update()` на каждом тике `EditorApplication.update`. Для **фронта** (`wasPressedThisFrame`, например Escape) вызывай только `QueueStateEvent`, без ручного `InputSystem.Update()`: иначе штатный апдейт плеерлупа съедает фронт и нажатие «не срабатывает».
  - `Unity_RunCommand` оборачивает код в namespace `Unity.AI.Assistant...`, где `Image` конфликтует с пространством имён пакета: пиши `UnityEngine.UI.Image` и `UnityEngine.UI.Image.Type`.
  - Сброс запаса нитро в тесте: `nitro.SendMessage("OnEnable")`. Выход в меню (Escape) и повторный вход пересоздаёт сцену целиком (`LoadScene` в режиме Single): все танки живые, кирпичи целые, так что это заменяет респавн, которого пока нет.
  - Касания в тестах: `Touchscreen` создаётся `InputSystem.AddDevice<Touchscreen>()`, касание — `InputSystem.QueueStateEvent(screen, new TouchState { touchId, phase, position, pressure = 1, startPosition, isPrimaryTouch })` на тике `EditorApplication.update` (Began, позже Moved/Ended; несколько `touchId` = мультитач). Позицию элемента бери из `RectTransformUtility.WorldToScreenPoint(null, центр GetWorldCorners)`. В конце `InputSystem.RemoveDevice(screen)` и отписка от `update`. Стик тянется ~90 пикс. на 0,62 пикс./ед. при окне 665 пикс. высотой (`Screen.height / 1080`).
  - **Значения ввода из `EditorApplication.update` читать нельзя:** `Gamepad.leftStick.ReadValue()` и `action.ReadValue()` там дают нули (читаются буферы редакторного апдейта), хотя `IsPressed()` кнопок работает. Результат проверяй сквозным путём: позиция и поворот `Rigidbody2D` танка (пишется в `FixedUpdate`) или состояние объектов в сцене.
  - `Unity_RunCommand`: `Navigation` тоже конфликтует с пространством имён пакета (`Unity.AI.Navigation`), как и `Image`: пиши `UnityEngine.UI.Navigation`. Префаб без загрязнения сцены собирай в `EditorSceneManager.NewPreviewScene()` + `SceneManager.MoveGameObjectToScene`, затем `PrefabUtility.SaveAsPrefabAsset`, `DestroyImmediate`, `ClosePreviewScene`; правка готового префаба — `PrefabUtility.LoadPrefabContents` / `SaveAsPrefabAsset` / `UnloadPrefabContents` (поля через `SerializedObject`).
  - После добавления `.cs` мост может молчать 3–5 минут и не оживает, пока окно Unity без фокуса: попроси пользователя переключиться на Unity. Ожидание делай фоновой командой (`run_in_background` с `sleep`), а не цепочкой коротких `sleep`.
  - Перед тестом убедись, что стены физически есть (`shapeCount`, `Physics2D.Raycast` по слою `Wall`): из-за бага 6.6 выше их может не быть.
  - **Не открывай сцену (`EditorSceneManager.OpenScene` в режиме Single), пока активная сцена с `isDirty == true`:** несохранённые правки пользователя пропадут. Проверяй `isDirty` и, если сцена грязная, останавливайся и спрашивай. Опасно и «сохранить за него»: в грязной сцене могут быть его ручные правки.
  - `OpenScene` и правка найденных после него объектов (`SerializedObject` + `ApplyModifiedProperties`) в одном `Unity_RunCommand` один раз не сохранили значения (ссылки остались `null`): открывай сцену одним вызовом, правь следующим и читай значение обратно.
  - Ускорение тестов: `Time.timeScale = 3` в Play Mode (окно без фокуса тикает ≈0,4× реального времени). Перед остановкой вернуть `1`. Наблюдатели на `EditorApplication.update` считай по игровому `Time.time`, а не по `realtimeSinceStartup`.
  - `Unity_GetConsoleLogs`: ставь `includeStackTrace: false` и малый `maxEntries` (2–10), иначе ответ раздувается стеками (особенно строки «-N HP» от `TankHealth`).
  - Расстановка объектов в сценах скриптом: точка свободна, только если в её клетке есть тайл `Ground` и нет тайлов `Border/Steel/Bricks/Water` (иначе легко поставить танк за границей карты, где тайлов нет вообще).
  - Обработка пользовательских правок в сцене: пользователь вручную выключает компоненты ботов (`TankWeapon`, `TankNitro`) для проверок; перед тестами поведения читай, что у ботов включено (`GetComponents<Behaviour>()`, `enabled`).
- Ощущение от игры проверяет человек. После фичи скажи, что именно проверить в Play Mode и какие параметры крутить в инспекторе.

2. Стрельба, кирпич/сталь/вода/кусты.
3. Простые боты: путь + атака. *(сделано)*
4. Нитро и таран. *(сделано)*
5. Основа меню (`Scenes/Menu.unity`, кнопки запуска тестовых сцен). *(сделано)*
6. Экранное управление (стик, выстрел, нитро, смена снаряда), чтобы раньше отдавать APK на тесты. *(сделано, ждёт проверки на телефоне)*
7. Павер-апы и смена типа снаряда. *(сделано, ждёт плейтеста)*
8. Состояния ботов, увороты, характеры. *(часть 1 сделана; тактический слой «Тактика ботов» в основном отложен: см. «Следствия режимов для кода»)*
8а.
